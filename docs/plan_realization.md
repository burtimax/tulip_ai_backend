# Dev Plan (MVP): Chat processing backend

Документ адаптирован под текущую структуру проекта и режим разработки чата с асинхронной обработкой сообщений (текст/изображения) через PlantId + OpenRouterService.

## Текущая структура, на которую опирается план

- `Api` — вход в систему, middleware, endpoints, DI, конфигурация.
- `Application` — сервисы и бизнес-логика use-case уровня.
- `Infrastructure` — EF Core, `AppDbContext`, сущности, миграции, persistence.
- `Shared` — конфиги, контракты результата, модели, утилиты.
- `SharedServices` — общие сервисы и внешние интеграции.
- `ConsoleTest` — тестовые/вспомогательные консольные сценарии.

## Правила ведения плана

- [ ] Выполнять эпики последовательно с учётом зависимостей.
- [ ] Перед началом задачи менять чекбокс на `[-]`.
- [ ] После завершения ставить `[x]` и фиксировать артефакт (PR/док/миграция/тест).
- [ ] Если требуется решение по архитектуре — помечать `[!]`.

Статусы:
- `[ ]` не начато
- `[-]` в работе
- `[x]` завершено
- `[!]` блокер

## Epic 5. Worker pipeline в `Application`

**Зависимость:** Epic 3 и Epic 4.

### 5.1 Оркестрация статусов
- [ ] Переключение `Queued -> Processing -> Completed/Failed`.
- [ ] Корректное выставление `Chat.Status` по агрегату сообщений.
- [ ] Защита от повторной обработки завершенной задачи.

### 5.2 Обработка изображений через PlantId
- [ ] Для каждого изображения последовательно вызывать PlantId `create identification`.
- [ ] Извлекать top-гипотезы по растению и болезням.
- [ ] Сохранять normalized + raw результат по каждому изображению.
- [ ] Агрегировать результаты по всем изображениям сообщения.

### 5.3 Формирование и отправка prompt в LLM
- [ ] Формировать prompt из агрегированного PlantId-контекста.
- [ ] Добавлять пользовательский текст в prompt (если есть).
- [ ] Отправлять запрос в `OpenRouterService`.
- [ ] Сохранять ответ как `Assistant` message в текущий чат.

### 5.4 Финализация
- [ ] Помечать исходное сообщение как `Completed`.
- [ ] При ошибке корректно помечать `Failed` и фиксировать причину.
- [ ] Обновлять `Chat.UpdatedAt`/`LastMessageAt`.

**DoD эпика:** worker полностью обрабатывает сообщение и добавляет ответ ассистента в чат.

## Baseline

- В `DomainParser.sln` присутствуют целевые проекты backend-слоёв: `Api`, `Application`, `Infrastructure`, `Shared`, `SharedServices`, `ConsoleTest`.
- Базовая композиция в `Api` уже может быть использована как host для chat endpoints и фонового worker-а.
- В `Infrastructure` уже есть база для развития EF Core модели (контекст/миграции/конвенции), которую нужно расширить chat-сущностями.
- Спецификация чат-пайплайна (PlantId -> prompt -> OpenRouterService -> ответ в чат) зафиксирована в этом документе и служит источником реализации.
- Стратегии retry/наблюдаемости и окончательные операционные runbook требуют доведения в Epic 7.
